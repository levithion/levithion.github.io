Neural Collaborative Filtering Movie Recommender

CineMatch is a personalized movie-discovery product built around a PyTorch NCF model, a hybrid recommendation engine, a FastAPI service, a Streamlit client, and persistent user taste data.

From model to product

A recommender must estimate preference from sparse observations, but a useful product also needs accounts, a catalogue, search, metadata, persistence, and a way to handle movies that have never appeared in the training data. CineMatch extends the original NCF project into that complete discovery loop: users sign up, rate films, browse or search for titles, and receive recommendations tailored to their taste.

The initial MovieLens small dataset contributes roughly 100,000 ratings across 600 users and approximately 9,000 movies. The repository also supports IMDb-linked OMDb search, allowing a user to import a title outside the original catalogue and keep it in a local CineMatch library.

Model architecture

The collaborative component implements an ItemBasedNCF model in PyTorch. User and movie IDs are mapped to separate 64-dimensional embeddings, concatenated into a 128-dimensional vector, and processed by a multilayer perceptron. The network uses 128, 64, and 32 hidden units with ReLU, batch normalization, and 0.3 dropout, then adds learned user, movie, and global biases. Its output is clamped to the valid 0.5–5.0 rating range.

  • Learned representations: independent embedding tables capture latent factors for users and movies.
  • Non-linear interaction: dense layers of 128, 64, and 32 units use ReLU activations, batch normalization, and 0.3 dropout.
  • Bias correction: learned user, movie, and global bias terms capture systematic rating tendencies outside the interaction network.
  • Bounded output: the final estimate is clamped to the valid 0.5–5.0 rating range.

Hybrid recommendation generation

At startup, the backend rebuilds stable mappings between MovieLens identifiers and contiguous embedding indices, loads final_model.pth onto MPS, CUDA, or CPU, and prepares a TF-IDF matrix from each title and its genres. The API also computes catalogue popularity from rating counts and community averages.

When a user requests recommendations, the service builds a taste profile from their saved ratings and genres. Known movies receive a blended score from the NCF signal, content similarity, and popularity. Imported movies without learned embeddings follow a cold-start path based on content similarity and popularity. Already-rated movies are removed before the final list is sorted and returned.

Application architecture

The FastAPI layer owns model inference, hybrid ranking, catalog search, authentication, rating writes, watchlists, similar-movie queries, and OMDb integration. SQLite stores accounts, ratings, watchlists, and imported catalogue records. Pydantic request models constrain inputs such as ratings and Top-K values, while the model handler enriches responses with titles, genres, years, community ratings, and optional posters.

The Streamlit application consumes the API rather than loading the model directly. The resulting flow is a small but complete product: sign in, rate at least a few films, receive a “Picked for you” list, discover or import more titles, save a watchlist, and inspect the profile’s rating history.

Engineering trade-off

The NCF checkpoint is not retrained after every rating. New ratings are persisted immediately and shape the user’s content-based taste profile, while scheduled retraining can refresh collaborative signals later. This keeps the interactive app responsive without pretending that a static checkpoint has learned a new embedding instantly.

Evaluation and limitations

Offline quality should be measured with a held-out interaction split using metrics aligned to the product goal—for example RMSE for rating estimation and Hit Rate or NDCG for Top-K ranking. The repository documents the serving path but does not publish benchmark values, so the portfolio avoids inventing them.

New users still need to rate a few films before recommendations unlock, and the NCF checkpoint remains fixed between retraining runs. The local SQLite store is appropriate for a demo but needs a persistent disk or managed database in production. Candidate scoring is also intentionally simple and would benefit from batching and model-version metadata at larger scale.

What the project demonstrated

This project connected model training with the less glamorous work that makes recommendations usable: identifier mapping, hybrid scoring, cold-start handling, authentication, persistence, metadata enrichment, API contracts, and a focused interface. The result is not only a neural network that predicts ratings, but a product that gives those predictions a practical place to live.
